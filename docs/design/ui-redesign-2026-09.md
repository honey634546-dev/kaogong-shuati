# 考公刷题 · 全新界面设计方案 v1.0

> 设计语言：**「砚台 Inkstone」** — 墨（结构）· 纸（底色）· 朱批（反馈）
> 覆盖：Web 端 + Capacitor Android App（同一套代码、双模式）
> 状态：方案定稿，待评审 → 分阶段落地
> 配套原型：`docs/design/ui-redesign-prototype.html`（7 个核心页面高保真稿，含深浅双模式）

---

## 0. 一句话结论

**现在的界面是"一个功能齐全的题库目录"；新界面要把它变成"一个管住备考节奏的教练"。**
题库、AI、错题本这些能力一个不少，但入口、层级和视觉重心全部重排——让用户打开 App 的第一秒就知道"我现在该做什么"，而不是"我该点哪个菜单"。

## 1. 第一性原理：从底层事实推导设计

### 1.1 先问：这个产品到底是什么？

不是"题库"。题库只是燃料。产品的真实身份是：

> **一个把「96,000 道题 + 5 个 AI 智能体」组织成「每天该做什么」的备考节奏管理器。**

用户不会因为"有 2455 套卷"而每天打开它；用户会因为"它知道我弱在哪、并且告诉我今天先做这个"而每天打开它。
**这决定了首页不是目录页，而是行动面板。** 这是本方案与现状最大的分歧点。

### 1.2 五条底层事实（不可违背）

| # | 事实 | 证据 | 对设计的强制约束 |
|---|---|---|---|
| F1 | **备考是"考试日期驱动"的倒计时任务** | 国考/省考/事业单位有固定考期；行测有明确分值结构 | 界面必须让"还剩多少天 / 哪个模块拖后腿"随时可见 |
| F2 | **刷题是高频、碎片、可中断的行为** | 通勤 5min、午休 20min、睡前 30min；手机会被突然打断 | 单次会话必须能在 10 秒内进入、任意时刻安全退出、退出不丢进度 |
| F3 | **核心循环只有五步：读题 → 判断 → 提交 → 看解析 → 订正** | 全产品 90% 的使用时长花在这里 | 做题页是"主屏"，其余所有页面都是它的服务员 |
| F4 | **错题是唯一会复利增长的资产** | 一轮刷完，题量收益归零；分数增长只来自错题清零 | 错题本要从"一个列表"升级为"一条有终点的工作流" |
| F5 | **App 版完全离线、无登录、数据在本机** | `local-handler.js` + IndexedDB + sql.js，零服务依赖 | 界面不得出现任何"网络不可用"式挫败；AI 是增益而非前提 |

### 1.3 从事实推出的六个设计判断

1. **首页 = 今日行动面板**（F1+F2）→ 一个主行动 + 三个今日任务，其余下沉。
2. **做题页优先于一切**（F3）→ 题干字号最大、点击区最大、操作在拇指区；元信息全部折叠。
3. **导航按"用户目标"而非"功能模块"组织**（F1+F2）→ 删掉"智能组卷""收藏"这两个低频 Tab，换成"今日 / 刷题 / 错题 / 我的"。
4. **错题本要有"掌握度"和"清零进度"**（F4）→ 引入掌握度衰减模型与"一键重做待攻克"。
5. **AI 必须是上下文按钮，不是设置项**（F3）→ 全局悬浮球，在题目页变"问 AI"、在申论页变"批改"、在错题页变"错因归纳"。
6. **离线优先的视觉表达**（F5）→ 数据本地感（"已保存在本机"）、AI 未配置时给"可读降级"而非报错。

## 2. 设计目标与适用场景

### 2.1 设计目标（三层，可验收）

| 层 | 目标 | 可衡量指标 |
|---|---|---|
| **L1 能用** | 任意场景下 10 秒内开始做题；任意时刻可安全中断 | 冷启动 → 首题呈现 ≤ 3 次点击；练习退出 0 数据丢失 |
| **L2 好用** | 用户不用思考"该刷什么"；薄弱点自动浮出 | 首页"今日任务"点击率 ≥ 60%；错题重做使用率 ≥ 40% |
| **L3 想用** | 有"今天又推进了一步"的完成感；愿意每天打开 | 7 日留存 ≥ 45%；连续打卡中断率下降 |

### 2.2 适用场景（5 个，界面必须全部覆盖）

| 场景 | 时长 | 设备/姿态 | 网络 | 界面要求 |
|---|---|---|---|---|
| **S1 通勤碎片** | 5–10 min | 手机 · 单手 · 站立晃动 | 4G 不稳 | 一键开刷、大点击区、可随时退出、离线可用 |
| **S2 午休刷题** | 15–25 min | 手机 · 双手 · 桌面 | WiFi | 支持章节专项、连续作答不打断 |
| **S3 睡前复习** | 20–40 min | 手机 · 躺姿 · 单手 | WiFi | 深色模式舒适、错题重做、低刺激配色 |
| **S4 周末模考** | 90–120 min | 手机/平板 · 横屏或竖屏 | 离线 | 计时、答题卡全局跳转、交卷保护 |
| **S5 桌面深度复盘** | 30–60 min | 笔记本 · 键鼠 | WiFi | 宽屏双栏（题目+解析/材料并排）、快捷键、hover 态 |
| **S6 申论作答** | 40–90 min | 手机/桌面 | 可离线 | 长文输入、字数统计、材料对照、AI 批改 |

### 2.3 明确不做（Non-Goals）

- ❌ 不做社交/排行榜/组队打卡 —— 备考是孤独的，社交压力反而劝退。
- ❌ 不做游戏化积分商城 —— 目标用户是 20–30 岁成年人，不吃虚拟徽章。
- ❌ 不做课程/直播/卖课入口 —— 本产品定位是工具，不是流量池。
- ❌ 不在首页堆"推荐课程/热门试卷" —— 首页只回答"我今天做什么"。

## 3. 目标用户画像

### 3.1 三类核心用户

**P1 · 应届全职备考「小李」** — 22 岁，本科应届，全职备考国考/省考
- 每日 6–8h，手机 + 笔记本双设备；追求刷题量与正确率
- 焦虑源：**进度不可见**（"我到底复习到哪了？"）
- 核心诉求：清晰的进度体系 + 章节树 + 模考
- 界面要求：信息密度可以高，但必须**有序**；桌面端要能双栏

**P2 · 在职碎片备考「张姐」** — 27 岁，在职考事业单位
- 每日通勤+午休+睡前合计 1.5h，**几乎全程手机单手**
- 焦虑源：**时间太少，怕选错题**（"我只有 20 分钟，刷什么最划算？"）
- 核心诉求：一键开始 + 系统替我决定刷什么 + 随时能停
- 界面要求：**单手可达、零决策成本、可中断**；深色模式刚需（睡前刷）

**P3 · 二战冲刺「老王」** — 29 岁，二战省考，已刷完一轮
- 每日 3–4h，核心动作是错题重做与弱项突破
- 焦虑源：**不知道自己是真会了还是记住了答案**
- 核心诉求：错题掌握度、弱项分析、模考数据
- 界面要求：**数据驱动**、错题闭环、正确率趋势要看得见

### 3.2 用户任务（JTBD）与当前痛点

| 用户内心的话 | 现状问题 | 新方案对策 |
|---|---|---|
| "我有 10 分钟，现在做什么最值？" | 首页 7 个快捷入口 + 4 张科目卡 + Hero，**无优先级，决策成本高** | 今日任务卡：系统按薄弱点生成 3 件事，第一件直接可点 |
| "上次刷到哪了？" | 每次进入都是随机新题，**无续接** | "继续上次"常驻首页第二卡 |
| "我错在哪一类？" | 错题本只有平铺列表，**无分类无掌握度** | 按知识点分组 + 掌握度衰减 + 一键重做 |
| "AI 怎么用？" | AI 藏在设置页，要先填 API Key，**首次门槛高** | 上下文悬浮球 + 未配置时的降级引导 |
| "我进步了吗？" | 统计分散在 Hero / 记录页 / 学习顾问 | "我的"里统一周报，首页放本周迷你趋势 |
| "这个模块我到底行不行？" | 科目卡只显示"已做/总题"，**无正确率无薄弱标记** | 树节点显示 题量 · 已做 · 正确率 · 薄弱徽标 |

### 3.3 使用环境约束（硬约束）

- 设备宽度以 **375–430px** 为基准设计，桌面 1024–1440px 做增强而非拉伸
- 单手拇指可达区 = 屏幕下方 **1/3**，所有高频操作放这里
- 光环境覆盖：地铁强光（需高对比）↔ 睡前全黑（需深色低亮度）
- 网络：S1 场景可能完全无网，S4/S6 可能离线 —— **界面不得把离线当异常**

## 4. 整体视觉风格与配色

### 4.1 设计语言「砚台 Inkstone」

**立意**：行测申论的本质是"做题 → 被批改 → 订正"。中国文人书桌上最核心的三个物件——**砚（墨池）、纸（宣纸）、朱批（红笔批注）**——恰好对应界面的三层角色：

| 意象 | 界面角色 | 表现 |
|---|---|---|
| **纸** | 底色与容器 | 微暖白纸底（不用冷灰白），卡片浮于纸面之上 |
| **墨** | 文字与结构 | 近黑带蓝的墨色正文，粗细分明的墨色层级 |
| **朱批** | 反馈与批注 | 朱砂红只用于"错、批注、关键提醒"，是情绪最高点 |
| **竹青** | 掌握与正确 | 做对、已掌握、连续打卡 |
| **琥珀** | 待办与进度 | 今日待办、进度条、未完成 |

**为什么换掉现在的 iOS 系统蓝？**
现在的 `#007aff` + hairline 是无个性、也无记忆点的"系统默认观感"，且蓝色饱和度高、长时间阅读刺激强。新方案用**低饱和靛墨蓝**做主色，长时阅读更稳，且与"粉笔蓝""华图蓝"形成区分；用**朱批红**建立独有的产品符号——看到红色就想到"这里错了，要订正"，这是学习类产品最值钱的情绪钩子。

**设计气质关键词**：静、稳、有据、被批改过。不炫技、不发光、不用渐变。

### 4.3 字体与排版

**字体栈**（零加载成本，符合离线要求）：
```
-apple-system, "SF Pro SC", "PingFang SC", "HarmonyOS Sans SC",
"Source Han Sans SC", "Microsoft YaHei", system-ui, sans-serif
```
**数字**：`font-variant-numeric: tabular-nums` —— 计时器、正确率、题量不跳动。

**字号阶梯（移动端基准 16px）**

| 用途 | 字号/行高 | 字重 | 说明 |
|---|---|---|---|
| 题干正文 | 19 / 1.75 | 400 | **全站最大阅读字号**，最重要的内容 |
| 页面大标题 | 24 / 1.3 | 700 | "今日""刷题" |
| 卡片标题 | 17 / 1.4 | 600 | |
| 正文 | 15 / 1.65 | 400 | |
| 辅助信息 | 13 / 1.5 | 400 | 元信息、时间、题量 |
| 标签/徽标 | 11 / 1.2 | 600 | 加 `letter-spacing: .04em` |
| 统计数字 | 30 / 1.1 | 700 | tabular-nums |
| 选项字母 | 16 / 1 | 600 | A/B/C/D |

桌面端整体上调 1px，题干 20px，最大阅读宽度限制 **680px**（超过会破坏中文阅读节奏）。

### 4.4 间距 / 圆角 / 阴影 / 图标

- **间距**：4pt 网格 —— 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40；卡片内边距 16，卡片间距 12，分组间距 24
- **圆角**：卡片 `18px`，控件 `12px`，小元素 `8px`，胶囊 `999px`，手机外框 `44px`
- **阴影**（浅色）：
  - 静止卡片：`0 1px 2px rgba(23,25,28,.04), 0 8px 24px -12px rgba(23,25,28,.10)`
  - 浮起/弹层：`0 2px 6px rgba(23,25,28,.06), 0 24px 48px -16px rgba(23,25,28,.20)`
  - 深色：降低不透明度 + 加强 `--line` 描边
- **图标**：统一 **1.8px 描边 / 24px 网格 / 圆角端点**，直接复用现有 `ICO` 线性图标库（`app.js` 已内置 40+ 个），不引入图标字体

### 4.5 动效规范

| 场景 | 时长 | 曲线 |
|---|---|---|
| 页面切换 | 220ms | `cubic-bezier(.32,.72,0,1)` |
| 答案反馈滑入 | 240ms | 同上 |
| 解析展开 | 260ms | 同上 |
| 按钮按压 | 120ms | `ease-out` |
| 进度环/进度条 | 600ms | `ease-out` |

**纪律**：动效只用于表达"状态变化"和"空间关系"，不用于装饰。全部尊重 `prefers-reduced-motion: reduce`（降级为 0ms 直接切换）。

### 4.6 深浅双模式

- 跟随系统为默认；顶栏提供三态切换（跟随 / 浅 / 深），选择写入 `localStorage`
- 首屏用内联脚本预设 `data-theme` 防闪烁（**现有 `index.html` 已实现，直接沿用**）
- 双模式必须**信息层级等价**：不能出现"深色下某个状态看不出来"

## 5. 信息架构

### 5.1 现状问题（导航层）

当前底部 4 Tab：`首页 / 智能组卷 / 错题 / 收藏`

| 问题 | 说明 |
|---|---|
| 频次错配 | "智能组卷"是**任务**不是**区域**，一周用 1–2 次却占了 25% 导航位 |
| 频次错配 | "收藏"使用率低（当前 0 条数据），却占了导航位 |
| 高频下沉 | "笔记""练习记录""AI 设置"高频但藏在首页快捷入口网格里 |
| 首页过载 | Hero + 4 科目卡 + 自定义题库卡 + **7 个快捷入口** = 4 个并列视觉重心 |
| 无优先级 | 用户进来必须自己判断"今天点哪个" |

### 5.2 新信息架构（4 Tab + 1 全局）

```
┌──────────────────────────────────────────────────────────┐
│  今日 Today        ← 行动面板（默认落地页）               │
│   ├ 考试倒计时 · 连续打卡                                  │
│   ├ 今日任务 ×3（系统按薄弱点生成）★主行动                │
│   ├ 继续上次                                              │
│   ├ 本周概览（迷你趋势 + 正确率）                          │
│   └ 科目快捷 ×4（横滑）                                    │
├──────────────────────────────────────────────────────────┤
│  刷题 Practice     ← 选择与开始                            │
│   ├ 搜索题目/试卷                                          │
```

### 6.8 五个关键交互流程

**流程 A · 碎片时间 5 分钟（S1，P2 用户最高频）**
```
解锁 → 打开 App（App 版跳过登录，直接落地"今日"）
 → 首页今日任务第一项高亮 [继续做：错题重做]
 → 点击 → 直接进入做题页第 1 题（≤3 次点击，≤10 秒）
 → 答 3 题 → 地铁到站，按返回
 → 弹确认："保存进度并退出" → 进度存入本地
 → 下次打开：首页"继续上次"显示"错题重做 第 3/32 题"
```

**流程 B · 专项突破（S2，P1/P3）**
```
刷题 Tab → 行测分组 → 看到"数量关系 42% [薄弱]"
 → 整行点击 → 立即开始 15 题（默认题量）
 → 连续作答 → 答错时解析自动展开
 → 结算页 80% → 主按钮"去攻克这 3 道错题"
 → 直接进入错题重做
```

**流程 C · 错题清零（S3，P3 核心动作）**
```
错题 Tab → 掌握度环显示"待攻克 32"
 → 底部 [一键重做待攻克（32 题）]
 → 按知识点分组依次出题 → 做对 2 次的自动移入"已掌握"
 → 结算 → 掌握度环从 77% → 82%（可见的进步）
```

**流程 D · 申论作答与批改（S6）**
```
刷题 Tab → 申论 → 归纳概括
 → 作答页：上=材料（可折叠）/ 下=作答区（富文本 + 实时字数）
 → 写满字数要求 → [提交批改]
 → AI 返回采分表：要点1 ✓3分 / 要点2 ✕0分 / 要点3 △1.5分
 → [对照参考答案] → 高亮 diff（我的答案 vs 参考）
 → [存入笔记] → 自动归档到"我的笔记"
```

**流程 E · 做题卡壳问 AI（S1–S5 通用）**
```
做题页遇到不会 → 点右下 AI 悬浮球
 → 半屏抽屉上滑："这道题怎么解？"（自动带入题干+选项+我的作答）
 → AI 流式返回 → 可继续追问 → 关闭抽屉
 → 回到原题，位置与作答状态完全保留
```

## 7. 为保证易用性所遵循的设计原则

| # | 原则 | 具体落地要求 | 验收方式 |
|---|---|---|---|
| 1 | **拇指优先 Thumb-first** | 所有高频操作（提交、下一题、重做）位于屏幕下 1/3；顶部只放"返回/进度/答题卡"等低频或状态类控件 | 375px 单手可达性走查 |
| 2 | **一屏一主行动** | 每个页面只允许一个实心主按钮；其余动作为描边/文字按钮 | 逐页截图检查主按钮数量 = 1 |
| 3 | **进度永远可见** | 任何时刻用户能回答"我在哪 / 还剩多少 / 我进步没"：做题页有 3/15、错题本有掌握度环、首页有周趋势 | 三个问题在界面上均可 3 秒内找到答案 |
| 4 | **零静默丢失** | 练习退出必确认；作答实时落盘；结算即写库。禁止任何"关掉就没了"的路径 | 强杀进程后数据完整 |
| 5 | **状态可见（Nielsen #1）** | 加载→骨架屏（非全屏 spinner）；AI→流式输出 + 停止按钮；离线→角标提示"已离线，AI 不可用"而非报错 | 每种异步状态都有明确视觉反馈 |
| 6 | **离线优雅降级** | 不依赖网络的功能不显示任何网络错误；AI 相关入口在未配置/离线时降级为"去配置"或隐藏 | 飞行模式下全流程走通 |
| 7 | **认知负荷最小化** | 题干优先，元信息（难度/年份/来源）一律 13px 弱化或折叠；材料默认收起 | 首屏信息层级 ≤3 层 |
| 8 | **手势必须有替代** | 滑动切题、长按标记等手势，一律提供可点击的等价入口 | 全功能可仅用点击完成 |
| 9 | **无障碍** | 正文对比度 ≥4.5:1；点击区 ≥44×44px；支持系统动态字体；尊重 `prefers-reduced-motion`；所有图标按钮有 `aria-label` | axe 扫描 0 critical；对比度脚本校验 |
| 10 | **双主题等价** | 深色不是浅色反色，语义色需重新打光；两模式下信息层级、状态可辨识度完全一致 | 双模式逐页并排比对 |
| 11 | **可预期的返回** | 维护显式导航栈（现有 `store.navStack` 已实现），返回永远回到来的地方；全屏页（做题）返回有明确出口 | 任意深度页面连按返回可回到今日 |
| 12 | **性能即体验** | 首页骨架屏 + 数据异步填充；题库查询走本地 sql.js（2ms）；列表虚拟化（错题 >100 条时） | 首屏可交互 < 500ms；滚动 60fps |

## 8. 响应式与平台适配

| 断点 | 布局 | 差异 |
|---|---|---|
| **< 640px（手机，基准）** | 单列，底部 Tab | 主设计形态 |
| **640–1023px（平板/折叠屏）** | 单列 + 最大宽度 680px 居中；底部 Tab 保留 | 题干 20px |
| **≥ 1024px（桌面）** | **双栏**：左 = 导航侧栏（替代底部 Tab），右 = 内容；做题页支持"题目 / 解析"并排 | 支持 hover 态、键盘快捷键（1-4 选项、Enter 提交、←→ 切题） |

**桌面不是手机版的拉伸**：≥1024px 时底部 Tab 换成左侧边栏（图标 + 文字），做题页启用双栏——左侧题干与选项，右侧常驻解析与 AI，这是 P1 用户"深度复盘"场景（S5）的刚需。

## 9. 落地路线（映射到现有代码）

现有前端是**零构建的原生 SPA**（`public/index.html` + `app.js` + `style.css`），因此改造可分阶段、可灰度、可回滚。

### 阶段 1 · 视觉换血（0 逻辑改动，风险最低）
- `public/style.css`：替换 `:root` / `[data-theme="dark"]` 全部 token 为「砚台」色板；调整圆角/阴影/字号阶梯
- `public/index.html`：`theme-color` meta 改为 `#FBFAF8` / `#101215`；favicon 换为墨+朱批符号
- 产出：**全站即刻换新皮**，功能零回归

### 阶段 2 · 导航重构
- `public/index.html`：底部 4 Tab 改为 `今日 / 刷题 / 错题 / 我的`（图标复用现有 `ICO` 库）
- `public/app.js`：`setView()` 的 `showNav` 白名单同步更新；新增 `renderToday()` / `renderPracticeHub()` / `renderMe()`
- 原 `renderHome()` 内容拆分：Hero+科目卡 → `renderToday()`；快捷入口 → 下沉到 `renderMe()`
- 产出：信息架构切换完成

### 阶段 3 · 核心页面重做
- `renderPracticeHub()`：科目树节点加"已做 / 正确率 / 薄弱徽标"（需 `/api/subjects` 与 `chapterStats` 聚合，接口已具备）
- `renderQuestion()`：选项改答题卡方角标、反馈条原地滑入、解析分段 Tab
- `renderResult()`：大进度环 + "去攻克错题"主按钮
- `renderWrong()`：掌握度环 + 按知识点分组 + 错因标签 + 一键重做
- **掌握度模型**需新增字段（`wrong_mastery`：连续正确次数），在 `practice.db` 加列 + 本地 IndexedDB 同步

### 阶段 4 · AI 上下文化
- 新增全局 AI 悬浮球组件，按 `store.state.view` 切换文案与预设提示词
- 复用现有 `lib/ai-agents.mjs` 的 5 个智能体，不改调用逻辑
- 申论作答/批改页（`essay`）为新页面，需新增富文本作答区 + 采分表渲染

### 阶段 5 · 桌面端增强
- ≥1024px 断点：底部 Tab → 左侧边栏；做题页双栏
- 键盘快捷键

**优先级建议**：阶段 1 → 2 → 3 顺序做（每阶段可独立交付）；阶段 4/5 可并行。

### 落地过程中的三处设计修正

1. **掌握度不是「连续正确次数」而是「跨天正确天数」**：原方案写「新增 `wrong_mastery` 连续正确次数列」。实际落地改为派生口径 `okDays = COUNT(DISTINCT date(created_at)) WHERE is_correct=1`，阈值 3 —— 与既有的「跨不同日期做对 3 次自动移出错题本」规则同源，无需加列、无需数据迁移，也避免了两套口径互相矛盾。
2. **解析卡不做「考点 / 解析 / 技巧」三段**：题库只有单一 `analysis` 字段，拆三段属于凭空造数据。改为「官方解析 / AI 讲解」两段——信息来源不同、可靠性不同，分段才真正减少一次性信息量。
3. **材料题不叠加第三栏**：≥980px 已有「材料左 / 题目右」分屏，而 ≥1024px 又多了 216px 侧边栏；若在 ≥1180px 再挂右侧 AI 栏会挤成三栏、题目列不可读。故 AI 常驻栏在 ≥1440px 才启用（此时主列 980px 才放得下 430px 材料 + 480px 题目）。

## 10. 验收标准

**视觉**
- [ ] 全站无渐变、无彩色光晕；语义色仅用于语义（红=错/批注、青=对/掌握、琥珀=待办）
- [ ] 深浅双模式逐页并排比对，信息层级完全等价
- [ ] 所有正文文字对比度 ≥4.5:1（`--ink-3` 仅用于装饰/禁用/占位）

**交互**
- [ ] 冷启动到首题 ≤3 次点击、≤10 秒
- [ ] 375×812 下题干 + 4 选项零滚动完成
- [ ] 练习中途退出必确认，强杀进程后进度与记录完整
- [ ] 飞行模式下：刷题、判分、错题本、统计全部可用；AI 入口降级为引导

**可用性测试（5 人 × 3 场景）**
- 任务 1：给你 5 分钟，开始一次练习 → 成功率 100%，平均点击 ≤3
- 任务 2：找出你最薄弱的模块 → 成功率 ≥80%，平均耗时 ≤10s
- 任务 3：把 3 道错题重做一遍 → 成功率 ≥80%
- 任务 4：写一段申论并拿到批改 → 成功率 ≥60%（AI 配置前提下）

## 11. 风险与取舍

| 风险 | 影响 | 对策 |
|---|---|---|
| 换主色后用户不适应（尤其老用户） | 认知重置 | 阶段 1 先只换 token 灰度；保留旧主题选项一个版本 |
| 首页从"目录"变"任务"，老用户找不到入口 | 挫败 | "我的"里保留完整快捷入口；首次进入给一次性引导气泡 |
| 掌握度模型与现有 `practice_records` 语义冲突 | 数据迁移 | 新增独立字段，不改既有列；无该字段时降级为"未掌握" |
| 桌面双栏增加实现成本 | 工期 | 放在阶段 5，移动端优先，桌面可先只做居中单列 |
| 首页任务推荐依赖数据，新用户冷启动无数据 | 空态难看 | 空态设计为"开始刷第一道题"，并给 3 个科目入口 |
| 朱批红使用过量导致视觉疲劳 | 观感 | 严格限定：仅"错误/批注/危险操作"三类场景使用，禁止用于装饰 |
