# 判断题方法分析准入评估

本报告区分题型标签、完整文字题可否进行方法分析、模型内容正确性和用户可读性。它使用原创合成题与本机独立盲标，不是用户学习效果实验，也不证明真实用户已经提速。

## 固定的六道原创题

题干、标准答案与预期方法边界在任何真实调用前写入 `classification-method-cases.json`。

| 样本 | 内容 | 标准答案 | 必须核对的边界 |
|---|---|---|---|
| MC01 | 交付保管、约定用途、返还原物、所有权不转移 | A | 所有条件同时满足；同型号不能替代原物 |
| MC02 | 共同试验四条件，问“不属于” | C | 保留否定问法；投入/收益不等不是排除条件 |
| MC03 | 钥匙:开锁 | B | 工具→动作，顺序不能颠倒，作用对象不同于动作 |
| MC04 | 正方形:矩形:四边形 | A | 两层种属包含；不能混同部分整体或成员整体 |
| MC05 | 广告与延长营业同时变化，店长全归因广告 | B | 未排除其他可能原因，不断言广告无效或其他因素已造成增长 |
| MC06 | 三个条件定义“单次授权”，A使用关键词诱导 | B | 三要件缺一不可；父判断分类不妨碍按实际题面分析 |

MC01–04 的源 category 为定义判断/类比推理；MC05/06 的源 category 为父类判断推理。能力函数对后两题使用“文字判断”标签，模型分别选择因果归因核对和定义要件核对。评估同时验证能力函数和提示构建不修改原题对象或源 category。

## 第一轮真实评估：原结果保留

`classification-method-evaluation-live-v1.json`：仅调用一次固定六题，共 6 次真实 provider 请求，最多并发 2、每次 60 秒、无重试。角色为已有行测配置，模型 `deepseek-v4.1-flash`；用内存任务配置，不修改用户数据库或设置。只发送原创合成题。报告记录样本、core、classifier 三个 SHA256，含每次原始响应和独立审阅。

- 6/6 输入可分析，6/6 schema 完整，6/6 答案与核心解法正确。
- 5 题的方法边界核对通过；MC05 步骤里“延长营业时间也会影响销售额”表述过于确定，应为“可能影响”。其余字段虽说明是未排除的替代原因，该句仍保留为因果限定语警告。
- 5/6 文案不能直接交付：MC01/02/03/05/06 的 diagnosis 出现 `assisted`、`userReason`、`userApproach` 或 `null` 等调试字段。MC04 没有这些字段。反复强调猜测、未证明独立作答也增加了阅读负担。

因此本轮结论是“方法分析值得继续准入评估，但文案需要修正”，不是“六题全部达到交付质量”。结构合法、答案正确和面向用户可读是三个不同门槛。

## 预先限定的两题纠正复验

运行前固定：只复测 MC01/MC05，各一次，无重试，新增最多 2 次请求，总请求数上限为 8；结果另存 `classification-method-evaluation-targeted-v2.json`，不覆盖第一轮。

修复是系统提示要求自然中文，不暴露内部字段或值，diagnosis 通常一至两句；未记录过程时不自动展开猜测/辅助免责声明。因果证据不足的替代因素只写“可能”，不得写成已证明的原因。

验收条件：MC01 仍逐项核对四要件并选 A；MC05 仍选 B，保留其他原因的可能性而不认定其已实际造成增长；两题都保持严格结构且文案自然简短，不再出现内部字段或自动怀疑用户猜测的表述。该复验只支持评估两个修复点，不能重新宣称新版本六题全部通过。

复验实际结果：2/2 严格结构和核心方法通过，2/2 消除了内部字段。MC05 不再把延长营业时间写成已经证明的增长原因。但文案目标没有全部达到：MC01 的 diagnosis 仍为 3 句；MC05 为 4 句，且最后仍自动补充“未记录是否使用辅助，不能据此判断掌握程度或速度”。因此结论是“核心方法、字段泄露和因果限定语已修正，简洁性与默认辅助免责声明仍需产品处理”，不能称两题已完全达到可交付文案要求。

累计真实请求严格止于 8 次（首轮 6 次、定向复验 2 次），没有重采样。完整原始回复与门槛逐项判断保存在两个独立报告中，供最终准入决定。

产品随后采用确定性展示修复：用户未填写卡点和原解法时，界面不显示模型生成的个人诊断，固定显示“仅凭用时无法确定慢因。对照下面的解题步骤，找出与你当时做法不同的一步。”；信息不足的结果则提示先核对题目信息。填写自述后才展示基于该自述的模型建议。这符合没有过程证据不能诊断个人慢因的边界，不依赖继续请求模型直到碰到简短答案。

定向浏览器2/2通过：夹具故意返回内部字段和冗长辅助免责声明，空自述的实际页面仍只显示固定两句；有自述的个性建议保留，刷新历史后不把旧自述推给新请求。原始模型文案问题仍保留在报告中，不能声称模型本身已完全解决。没有追加真实调用。

## 独立盲标题型样本

只读当前本机 220 道父类判断题，在 6 个批次内各取 6 题。每批次按 `sha256('blind-v1:' + sourceUID)` 排序，跨批次去除相同题干/材料/选项组合后得到 36 个唯一可见题样本。先阅读实际题面、材料、选项完成语义标签，再允许对照自动 classifier；盲标时没有读取新 classifier 实现或预测。

标签分布为定义判断 11、类比推理 8、逻辑判断 8、图形推理 9。图形样本明确含缺图证据。该样本用于后续独立 precision/coverage 对照；本报告不自行把可分析覆盖率当作细类标签准确率。

固定标签后只读对照结果见 [classification-data-audit-v1.json](classification-data-audit-v1.json)：36题中自动给出24个细类，24个均与事先标注一致，12题保留父类；27道文字题全部可用、9道图形题全部不可用。没有根据保留父类的样本调参后重报成绩。事先标注来自独立代理而非领域专家，不能把24/24一致率外推为通用准确率。

标签只保存于 git 忽略的本机 `data/temp/method-classification-holdout-blind-v1.json`，每行仅 `id/sourceUID/label/evidenceCode`。没有把真实题面写入 Git 或发送给额外模型 provider，没有修改用户数据库。抽样与盲标仍然是有限样本，不代表完整题库或所有未来导入数据。

最终代码审查另从导入器的图形提示模板发现三类缺图句式漏拦：下面/以下/所给图形分组、左图给定多面体、外表面展开图。修复只扩充这些明确图形依赖句式，30次合成负例通过。最终覆盖统计另存 `classification-data-audit-final-v2.json`，可用题仍为406道、判断168道；原盲标对照与其classifier散列保持冻结，不把复用样本当作新的独立验证。最终六题离线合同检查见 `classification-method-evaluation-offline-final-v2.json`，六题入口仍可用，零新增provider请求；真实结果仍对应各自报告所载散列。

## 复跑入口

```sh
node scripts/evaluate-method-classification.mjs
node scripts/evaluate-method-classification.mjs --live
node scripts/evaluate-method-classification.mjs --live --ids=MC01,MC05 --revision=natural-copy-v2 --out=docs/speed-review/classification-method-evaluation-targeted-v2.json
```

实时模式拒绝覆盖已有输出文件；需要新评估计划才应使用新的输出路径。默认离线不请求模型。
