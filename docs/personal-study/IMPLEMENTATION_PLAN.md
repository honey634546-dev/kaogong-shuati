# 个人学习刷题工作台实施计划

本项目基于 `ERRRC/kaogong-shuati` 做受控二次开发，目标是本机优先、单人使用、支持自定义题库和随题多轮 AI 助教的学习工具。

## 产品边界

第一版必须走通：空目录启动 → 导入/编辑题库 → 练习与判分 → 错题/收藏/笔记 → 按题多轮追问 → 重启恢复 → 完整备份恢复。

第一版不做账号体系、商业题库爬虫、联网搜索、向量数据库、多 Agent、监考和原生客户端。主观题保存作答并支持 AI 讨论，但不宣称官方评分。

## 技术约束

- 保留 Node.js HTTP 服务、SQLite 和现有 Web 前端。
- `tiku.db` 是可选的只读兼容来源，不再是启动前提。
- 新数据统一放在 `APP_DATA_DIR`；旧版根目录数据必须可兼容读取或明确迁移。
- 默认只监听回环地址；API Key 不进入 GET 响应、日志、Git 和默认备份。
- API Key 默认只保存在当前浏览器页面内存中，不写入浏览器持久化存储，也不发送给本项目服务端；此模式由浏览器直连 OpenAI-compatible 网关，因此网关必须允许 CORS。
- 用户可显式切换为“存服务端”，此时 Key 才写入本机 `ai-config.db` 并由服务端代为请求；切回浏览器模式会清除服务端旧 Key。
- 没有 Key 时本地题库功能仍可用；AI 调用按保存模式分别走浏览器直连或服务端请求。

## 工作包

| 阶段 | 交付 | 门槛 |
|---|---|---|
| WP0 | 上游 commit、工作树、依赖、数据库、测试基线 | 现状和真实阻断有记录 |
| WP1 | 空库启动、统一数据目录、兼容迁移入口 | 无题库/无 Key/无外网可启动，重启不丢数据 |
| WP2 | JSON/CSV 导入预览、CRUD、材料、图片、稳定 ID/版本 | 重复导入幂等，冲突不静默覆盖 |
| WP3 | 服务端判分、作答快照、幂等提交、自测统计 | 改题不改历史，双击不重复 |
| WP4 | 模型配置、兼容请求、SSE、超时取消、本地 mock | 正常/异常协议测试通过 |
| WP5 | 随题上下文、多轮侧栏、历史恢复、切题隔离 | 真实多轮和换题不串话 |
| WP6 | 错题复做、收藏、笔记、旧会话 | 复习闭环可用 |
| WP7 | 完整备份恢复、安全/性能加固 | 新目录恢复后数据一致 |
| WP8 | 干净环境、浏览器全流程和条件验证 | 未测项明确列出 |

当前分支已完成 WP1/WP2/WP3/WP4/WP5，下一步进入 WP6；每个阶段都要记录命令、结果、限制和对应 commit。WP5 已把题目快照、当前作答和材料文本绑定到按版本隔离的会话，Web/本地两端都支持历史恢复、错误状态和停止请求。真实供应商与真实题库浏览器流程仍留到 WP8 验证。

## Key 保存策略实现状态

已完成：AI 设置页提供两种保存位置，默认“仅浏览器保存”。服务端增加 `key_storage_mode` 迁移字段；浏览器模式使用页面生命周期内存保存，并通过浏览器直连完成通用对话、随题会话、OCR/结构化和批改，服务端只接收必要的配置/结果落库请求。服务端模式保留原有本机配置库和请求代理能力。两种模式均不通过 GET 接口返回原始 Key；含图题的完整二段式解析仍需在 WP8 用真实供应商做浏览器验收。
